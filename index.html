01The problem

A tool call is not proof.

A computed figure and a generated figure are indistinguishable in text. A tool-call record establishes that a tool executed; it does not establish where the values entering it came from.

01 · DECIDE
Invoke the tool?
The model decides whether to compute at all — or to answer directly.
Probabilistic
02 · SELECT
Choose the operands
The model selects which values enter the computation.
Probabilistic
03 · EXECUTE
Compute
The tool runs the arithmetic exactly as specified.
Deterministic
04 · RELEASE
Report the figure
The model carries the result into the answer.
Probabilistic

Three of the four links are probabilistic. A deterministic component inside a probabilistic pipeline does not make the pipeline deterministic. The wrong input, a skipped calculation or a mistranscribed result still produces a number that looks right.

Output inspection cannot separate them

02The system

The model interprets. Code computes. Evidence travels with the figure.

Certanum is designed to partition the generative component out of the numerical path. What remains in the path is conventional deterministic software, developable to the assurance bar the domain requires.

01
Source
Authoritative source data, or a declared artifact bound by digest.
02
Resolve
Every operand resolves to its evidentiary origin.
03
Compute
A declared, deterministic operation produces the figure.
04
Record
Operands, operation and result are bound into an evidence record.
05
Re-execute
A third party can reproduce the figure from the record.
06
Release
Only a figure with a complete record leaves the system.
Refusal by construction

An operand that cannot be resolved does not degrade the answer. It withholds it. Refusal is a structural property of the architecture, not a policy applied to a model. Certanum does not certify the truth of the source data or the suitability of the domain logic; it establishes the derivation.

06Standard and system
AP-1 is open.
Certanum is not.

The measurement is open so the claim can be falsified. The system built to satisfy it is proprietary.

AP-1, the Admissibility Protocol, is an open standard for measuring whether a consequential figure produced by an AI system was computed, traceable, reproducible and refusable. It is authored by Marcus Rupp and published by ZORRZ Financial Inc. under CC BY 4.0, with a reference instrument under MIT — applicable by any party to any system, including Certanum’s, without the publisher’s involvement or consent.

Certanum does not control the standard and holds no certification, registry or accreditation role.
